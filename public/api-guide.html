Guía de API de Tomodachi

Conecta un agente de IA o una herramienta externa para consultar y, si lo autorizas, administrar la información de tu tienda mediante la API REST.

Importante: trata la clave como una contraseña. Se muestra una sola vez, no la publiques y revócala si alguien que no debe la conoce.

1. Permisos

Solo lecturaPermite consultar productos, categorías, clientes, ventas, reportes y configuraciones permitidas. Lectura y escrituraPermite consultar y también crear o modificar datos. La escritura incluye lectura automáticamente. Personalizar aparienciaPermite modificar únicamente el tema visual cuando el endpoint lo admite. No sustituye a lectura ni escritura.

Para un agente que debe revisar y administrar la tienda, selecciona Lectura y escritura. No necesitas marcar “Solo lectura” adicionalmente.

2. Cómo enviar la clave

Incluye el token completo en cada petición dentro del encabezado Authorization:

Authorization: Bearer TU_CLAVE_COMPLETA

La dirección base es la misma dirección donde está instalada Tomodachi. Por ejemplo:

BASE_URL="https://tu-dominio.example"
curl "$BASE_URL/api/inventory/products.php" \\
  -H "Authorization: Bearer TU_CLAVE_COMPLETA" \\
  -H "Accept: application/json"

3. Primer ejemplo: consultar productos

curl -sS "$BASE_URL/api/inventory/products.php" \\
  -H "Authorization: Bearer TU_CLAVE_COMPLETA"

La respuesta contiene product_id, product_name, price, cost, category_name, current_stock y otros datos del producto.

4. Endpoints principales

GET/api/inventory/products.php
GET/api/inventory/categories.php
POST/api/inventory/stock.php Ajustar existencias
GET/api/customers/customers.php
GET/api/sales/get_sales.php
GET/api/sales/sale_details.php?sale_id=ID
GET/api/reports/dashboard_stats.php
GET/api/reports/close_z.php
POST/api/sales/create_sale.php Crear venta
PUT/api/inventory/products.php Actualizar producto

La referencia completa de endpoints está en el repositorio, en docs/API.md.

5. Qué significan los errores

200 o 201: operación correcta.

401: clave inválida, incompleta, expirada o revocada.

403: la clave es válida, pero no tiene el permiso requerido.

404: endpoint o recurso inexistente.

422: faltan datos o hay un campo inválido.

6. Prompt para Claude, ChatGPT u otro agente

Copia este texto y sustituye los valores entre corchetes:

Actúa como asistente de administración de Tomodachi POS.
Base URL: [URL_DE_TOMODACHI]
Clave Bearer: [CLAVE_COMPLETA]

Usa la API REST enviando la clave en el encabezado:
Authorization: Bearer [CLAVE_COMPLETA]

Reglas:
- Consulta primero el estado actual antes de proponer o ejecutar cambios.
- Respeta exclusivamente la tienda asociada a esta clave.
- Para consultar productos usa GET /api/inventory/products.php.
- Usa solamente endpoints documentados.
- Antes de crear, modificar, cancelar o eliminar información, explica la acción y pide confirmación.
- Nunca muestres la clave en una respuesta pública ni la guardes en texto plano innecesariamente.
- Si recibes 401, indica que la clave es inválida, expirada o revocada.
- Si recibes 403, indica que falta el permiso necesario.
- Si recibes 422, revisa los campos enviados antes de volver a intentar.
- Guía de referencia: [URL_DE_TOMODACHI]/api-guide.html

7. Conexión con agentes

Tomodachi Community no necesita una integración propietaria con Claude u OpenAI: cualquier agente capaz de realizar peticiones HTTP puede usar esta API. La pantalla de Integraciones permite copiar la clave, copiar un prompt preparado y abrir esta guía.

Los botones “Claude” y “OpenAI” pueden añadirse posteriormente como asistentes de configuración, pero no deben enviar la clave automáticamente a un proveedor externo. La clave debe permanecer bajo control del dueño de la tienda.
